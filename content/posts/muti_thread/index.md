## 背景
之前多线程编程的时候，大部分都是使用***锁***和***条件变量***实现的临界区保护；有些时候却发现：代码在x86架构上跑的没问题，但是在ARM架构上跑的就不对了。后来才了解到arm架构和x86架构在内存barrier、cache coherency等方面有很大差异。也让我再次深入的了解了一下多线程编程混乱的核心原理。

### 1 . 指令的原子性
这和应该是大家最熟悉的；C/C++某个指令，会拆开成多条指令执行，比如：I++，在x86架构上，会被拆成两条指令;这样就导致在执行一个指令的时候，另外一个线程可以插入进来执行。
### 2. 代码的顺序性
c++的代码默认是从上到下顺序执行的，但是编译器为了提高效率，会将代码进行重排序。CPU为了提高效率，也会对代码进行乱序执行。
```cpp
// 线程 A：程序员写的代码
tail_.store(5, std::memory_order_relaxed);  // ①
flag = true;                                  // ②

// 经过优化或者CPU乱序执行：：② 先执行了
// 线程 B
if (flag) {           // flag == true ✅ （② 先执行完了）
    x = tail_.load(); // 但 tail_ 还是旧值 ❌ （① 还没执行）
}


```
